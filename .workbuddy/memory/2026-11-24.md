## 楼梯口“走不过去”第 2 轮：日志定案 —— 隐形护栏下摆伸到地面层
### 实测证据（`Unity/Editor.log`）
```
[卡住] 位置 (-21.31,1.38,-105.77) 推向 (0.99,0.00,-0.13) 挡路 Right Guard box((0.18,1.30,5.15))
       min(-20.82,0.62,-106.50) max(-20.64,4.30,-101.38)
[卡住] 四周：[0° Stair Walk Ramp] [45°/90°/135° Right Guard] [180° 通] ...
```
- `Left/Right Guard` 是**随坡道旋转(-29.7°)的薄板**（本地 0.18×1.30×5.15，父级 `Stair Walk Ramp`），
  不是竖直墙；世界 AABB 高度 3.68m 是倾斜+1.3m 高度叠出来的假象。
- 真正的问题：护栏比坡道**长**，下摆世界 z 到 -106.50，而坡道低端只到 -105.95 →
  楼梯口地面层被一堵看不见的 1.3m 墙封住（x≈-20.7 一整条）。
### 修法：新增 `Assets/Scripts/House/StairGuardFit.cs`
- AfterSceneLoad 找到 `Stair Walk Ramp` 碰撞体 + `Left/Right Guard`，把它们**靠地面那一端裁短**：
  目标 `ramp.bounds.min.z + 0.50`（让出楼梯最后半米，坡度高度只有 20~30cm）。
- 薄板是斜的，不能按 1:1 换算：`perUnit = |TransformVector(forward).z| ≈ 0.869`，
  `cut = (want - bounds.min.z)/perUnit`，`size.z -= cut`，`center.z += cut/2`（保留上端）。

## 床上玩偶“悬空”：是我上一轮的兜底把它顶上去了
- 日志：`[玩偶兜底] toy_1 ... 已挪到 (-23.988, 4.051, -92.941)（方向 (0.00,1.00,0.00)，挪了 0.240m）` ← 就是它。
- 根因：`SM_Bed_A1` 是**整个床一个大 MeshCollider**（含床头板，bounds 顶到 y≈4.05），
  玩偶靠床头摆着必然和这个大盒相交 24cm；兜底“往上顶直到不穿”就把它顶到空中。
- 修法（`PuzzleItemGuard`）：
  · 新增 `HasSupport(t,b)`：用脚底下方 (min.y-0.10 ~ min.y+0.02) 的 **OverlapBox** 判“站在家具上”。
    （不能用向下射线：起点在粗碰撞盒内部时 MeshCollider 从内部打不到背面，会误判悬空。）
  · `standing` 时**禁止任何竖直位移**、禁止缩小；水平也找不到空位就保持美术原位并打日志。
  · 悬浮在空中的玩偶（脚下没东西）仍走原逻辑，不受影响。

## 床上玩偶“悬空”第 3 轮：射线起点在身体内部 → 量不到被子表面
- 日志证据：`Editor.log` 里始终只有 `[玩偶兜底] toy_1 半截穿进柜体/墙，已挪到 (-23.988, 4.051, -92.941)（方向 (0,1,0)）`，
  **完全没有** `DropToSupport` 的任何输出 → 说明它走的是 `gap < 0.06` 的静默 return。
- 根因：旧 DropToSupport 从 `b.center` 往下打射线。玩偶被床的整块 MeshCollider 包住时，
  射线**起点在 mesh 内部**，MeshCollider 默认不打背面 → 打不到床面；能命中的只有玩偶自己的碰撞盒
  （底面就在脚底附近）→ gap≈0 → 静默返回 → 接下来 SettleOutOfFurniture 又把玩偶往上顶 24cm。
- 修法（`PuzzleItemGuard`）：
  · `FindSurface()` 抽出共用：射线起点抬到 `b.max.y + .75`（**必须在身体外面**），
    reach = 到脚底下 0.6m；5 条 probe（中心 + 四角 ×0.55）；**命中的点高于脚底的一律丢弃**
    （过滤玩偶自己的身体盒）；取最高有效面。
  · `DropToSupport` 用 FindSurface；落差 >60cm 视为量到地板，不动。
  · `HasSupport` 增加渲染/射线兜底：脚下 12cm 内有面也算“站住”。
  · `SettleOutOfFurniture` 的竖直位移**上限压到 6cm**（原来 35cm）：
    需要抬更高的都是被家具粗碰撞盒包住的美术摆位，抬起来就是悬空，宁可不动。
- 床 `SM_Bed_A1` 只有一个 GameObject + 一个 MeshCollider（含被子/枕头/床头板），
  所以拿碰撞盒或 Renderer.bounds 量表面都会虚高，只有“从外部打射线”能取到真实表面。

## 床上玩偶“掉落进床底”事故（第 4 轮修正）
- 第 3 轮的 `DropToSupport` 生效了，但落错层：
  `[玩偶落地] toy_1 悬在 SM_Floor_1-2-Attic_1200 上方 0.511m，已落到 ((-23.988, 3.302, -92.941))`
  → 直接落到**地板**（3.200），玩偶钻进床底，玩家完全看不见（截图实证）。
- 根因：`SM_Bed_A1` 的 MeshCollider **不含被子/枕头**（软装没有碰撞），从头顶往下打射线
  会穿过整张床直接命中地板，`gap=0.511` 就是“脚底到地板”的距离。
- **权威参照**：场景里 4 个 `StoryPlacement` 归位点的 y 是 **3.788~3.833**，
  而 toy_1 原位是 **3.811** —— 完全吻合，说明 3.811 才是“站在家具面上”的正确高度；
  之前被顶到的 4.051 才是悬空 24cm 的错位。
- 修法：`DropToSupport` 改成返回 bool；`gap > 0.35` 一律不下放，判定为“美术摆位”，
  返回 true 让调用处**连 SettleOutOfFurniture 也一起跳过**（完全不做任何位移）。
  调用处：`if (!DropToSupport(t)) SettleOutOfFurniture(t);`
- 教训：这类资源里“碰撞体 = 粗包围盒、软装无碰撞”，任何基于射线的落地测量都要有
  “落差过大就放弃”的硬闸门，否则一定把摆件送进地板。
